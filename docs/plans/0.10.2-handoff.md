### D. An anonymous count of active installs, sharing or not (owner, 2026-11-18)
- **The ask:** know how many people use rlx each day, those who don't share usage included: "no user tracking, just an anonymous active user count".
- **0.10.1 has none.**
  - Usage sharing is opt-in. While it is off (the default, or switched off), rlx sends nothing, apart from the one `opt_out` ping when someone switches it off (services/usage_share.py, its module docstring).
  - DO_NOT_TRACK, AISQUARE_NO_TELEMETRY and CI force it off.
  - So the backend's DAU, WAU and MAU count opted-in installs only. They come from `python manage.py rlx_metrics_report` and from Django admin: rlx → Installations and Usage days.
- **A shape to propose at intake:**
  - **The ping:** one small ping per local day on which rlx is used. It carries the date, the version, the OS, the architecture and the install method, and nothing else: no install id or other lasting identifier, no account or bearer, nothing about repos or usage.
  - **Once a day:** the client sends it at most once a day, so the count for a day is its number of active installs.
  - **The server** keeps counters per date, version and OS, and never stores the IP address. It is a new endpoint beside `/api/v1/rlx/metrics/` in AISquare-Studio-BE, shown in Django admin and in rlx_metrics_report next to the opted-in DAU.
- **For the owner to decide first:**
  - **WAU and MAU:** they need the same install recognised across days, and with no identifier only daily counts are possible. A random id that changes every month would give MAU without lasting tracking.
  - **Installs that switched sharing off:** do they still send the ping? The owner's ask says yes. An open-source audience calls an unannounced ping after a "no" tracking, so if they do:
    - the usage-telemetry doc (docs/usage-telemetry.md), the consent dialog and the Settings switch say the ping exists and is separate from usage sharing;
    - the ping has its own off switch;
    - DO_NOT_TRACK, AISQUARE_NO_TELEMETRY and CI stop it too.

### E. A tmux view in Settings (owner, 2026-11-19)
- **The ask**, in the owner's words: "settings page have a tmux manager view which shows all active tmux's, maybe pulling anything in? or just the tmux panes which are live because of rlx - basically give another avenue for managing".
- **What exists today** (the code at rc/0.10.2, which is v0.10.0's; where 0.10.1 differs, it says so):
  - **One private server.** Every agent runs on rlx's own tmux server, `tmux -L asq`, with a bundled config, so the user's own tmux sessions, config and prefix key are never touched (core/tmux.py, its module docstring and `DEFAULT_SOCKET`; `[fleet] tmux_socket` in core/config.py `FleetSettings`). Its socket is `tmux-<uid>/asq` under TMUX_TMPDIR, or under /tmp when that is unset (`TmuxServer.socket_path`).
  - **Its sessions:** one per project, `asq-<codename>`, with one window per agent, named by its label (services/fleet.py `SESSION_PREFIX`, `session_name`). Every window there opens through `open_window` (services/fleet.py), and the server also holds windows that run no agent, each kind in a session of its own:
    - `asq-accounts`: a Claude Code or Codex sign-in, window `account-<slot>` (services/claude_accounts.py `SIGN_IN_SESSION`);
    - `asq-persona-edit`: the persona editor (cli/ui/persona_dialogs.py `EDITOR_SESSION`);
    - `asq-watch`: `aisquare watch --detach` (services/watch.py `DETACHED_SESSION`).
  - **Which pane is an agent's:**
    - Its `fleet_agent` row holds the pane id (`%N`), the socket, the socket path tmux reported, and the server's start time and boot (models.py `FleetAgent`). The session name is not stored: it comes from the project's codename.
    - The fleet acts only where the row's launch record places the pane (core/launch_seal.py; services/fleet.py `resolve_place`), never on the row's own columns, which a sandboxed agent could rewrite to point at a pane of the user's.
    - A server numbers its panes from `%0` again after a restart, so a pane is the row's only on the server that was running when the row was written (`FleetAgent.server_started_at`).
    - A window that no row or record names is nobody's.
  - **When the agent is gone:**
    - The bundled config sets `remain-on-exit on` (core/tmux.py `BUNDLED_CONF`). An agent that exits or crashes leaves a dead pane with its last screen, and reads 💤 `exited` with its status. A pane that has vanished (killed by hand, the server stopped, a reboot) reads `lost`. Both are worked out on each read, never stored (models.py `FleetAgentState`; services/fleet.py `_derive`).
    - A server at the row's socket that started after the row is another server: the row is held and reads `unknown`, "another tmux server on its socket" (services/fleet.py `ANOTHER_SERVER`).
    - `aisquare fleet reap` records dead panes as ended and vanished ones as lost, releases their claims and removes finished worktrees. It closes no window (services/fleet.py `reap`). Doctor's `fleet` check names `aisquare fleet reap --all` when rows recorded live have no live pane (services/diagnostics.py `_check_fleet`).
    - An agent's window closes when it is stopped. A dead one closes when a restart under the same label is up (`_kill_dead`, which first asks again that the pane is dead), or at `fleet shutdown` (`_remove_lingering_windows`). Nothing closes a window that no row names.
  - **`fleet adopt` brings in a conversation, not a pane** (services/adopt.py, #290):
    - It lists the newest conversations no fleet row owns, from the transcripts under the accounts rlx knows: each agent's slots and its plain home (`recent`, 10 unless told).
    - It resumes one in a new rlx window with the agent's own resume (`claude --resume <path>`, `codex resume <id>`), on the account whose home holds it, in its own folder, as a coder unless told. Its session and board row stay its own (`adopt`).
    - It refuses while a live process still holds the conversation: Claude Code's `sessions/<pid>.json`, a process whose arguments name it, or a Codex holding its rollout open. It also refuses one a fleet row owns, and one whose folder is no onboarded project. So a Claude Code still running in the user's own tmux must quit before it can be adopted.
    - In the app it is the Accounts page's *Adopt a conversation…* picker (cli/ui/adopt_picker.py), which lists the held and not-onboarded ones with why. The UX audit's M6 moves it to the + menu.
  - **No screen lists tmux sessions or panes.**
    - The Settings hub (cli/ui/views/settings_hub.py) links App settings, Remote control, Captain, Accounts, Usage & stats, Agent resources and Doctor (0.10.1 adds Personas), above Fleet's Restart, Stop, Pause and Resume all.
    - Agent resources (cli/ui/views/resources.py) lists live fleet agents only (project, agent, role, account, CPU, memory, processes, uptime, tokens, cost) and acts on nothing.
    - Doctor's `fleet` row only counts the private server's sessions: "N live agent(s) across M session(s)".
    - A project's Settings tab shows the command that attaches a terminal to its session, `tmux -L asq attach -t =asq-<codename>` (cli/ui/views/settings.py `attach_line`). 0.10.1 drops that line (R13: asq names no command); `aisquare fleet attach` still attaches from a shell.
- **A shape to propose at intake:**
  - **A page of the Settings hub or a tab of App settings** that lists rlx's own panes: every window on the `asq` server, agent or not, read while the page shows, as Agent resources reads.
  - **Each row:** project (from the session's codename), the agent's label or "no agent" (from the fleet's rows and launch records, never the window's name), command (claude, codex, shell), age, alive (or dead, with its exit status).
  - **Actions:**
    - **Open:** an agent's pane opens its agent view; any other opens in a terminal pane, as the persona editor's does.
    - **Stop an orphan,** after a confirm that names it: a dead window, or a live one no row names.
    - **Adopt a live Claude Code or Codex pane into a project.** Adopt refuses a held conversation today, so this means: quit the agent in its pane (after a confirm), then resume its conversation in an rlx window, as `fleet adopt` does.
- **For the owner to decide first:**
  - **Scope:** only the tmux that rlx started, or every tmux server of the user?
    - Every server means reading sockets rlx did not make, in the user's `tmux-<uid>` folder under TMUX_TMPDIR: the user's own `default` server and other tools'. A server started under another TMUX_TMPDIR stays out of sight either way.
    - Even then, never type into or kill a session rlx did not start without a confirm that names it.
    - The safe default: rlx's own, plus read-only rows for the rest.
  - **What "pulling anything in" covers:** adopting only agent panes (Claude Code or Codex), or any pane, a plain shell included.
  - **Where it lives:** the Settings hub, or a tab of App settings.
- **Why it helps:** it finds panes and servers left running after a crash or a stop (orphans, leaked agent processes), and gives a way to manage them without a terminal.

## How the previous train ran (keep what helps)
- **Release train:** feature sub-PRs into `rc/**` get LEAN CI (Linux only). The full matrix, Windows included, runs on a push to `rc/**` or on a dispatch (`gh workflow run ci.yml --ref <branch>`). For each sub-PR:
  - dispatch the full matrix on its exact head;
  - have a tester verify that exact sha;
  - merge with `--match-head-commit <sha>`;
  - then watch rc's own push run.
- **Runners:** each push to `rc/**` also starts a duplicate full run for the rc -> main draft PR. Cancel it, and pause merging while a gate run waits for runners. The runner pool is shared org-wide.
- **Windows-only traps seen:**
  - "/" or "~" paths, or str(Path) compared with drawn text;
  - fleet calls without the in-memory tmux;
  - a stand-in binary that shutil.which cannot see on Windows (no PATHEXT);
  - widget ids reused before Textual frees them;
  - Textual timers holding executor threads.
  Reproduce on macOS by taking tmux off PATH, clearing the stand-in's exec bit, or using PureWindowsPath.
- **Before a coder says ready:** run every test file that imports a changed module, plus every test that greps a changed string. Paste each gate's last line (ruff check, ruff format --check, mypy, mypy --platform win32).
- **Nightly legs:** the `latest` Claude Code and Codex legs catch upstream drift. The 2.1.326, 2.1.327 and Codex 0.169.1 changes all arrived that way. They decide no PR, but each drift became a fix.
